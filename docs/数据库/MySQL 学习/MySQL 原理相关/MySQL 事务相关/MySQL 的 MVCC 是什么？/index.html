MySQL 的 MVCC 是什么？

基础概念类问题​

1. 什么是MVCC？它解决了什么问题？​

考察点： 对数据库并发控制机制的理解

参考答案： MVCC（Multi-Version Concurrency Control，多版本并发控制）是一种并发控制机制，通过维护数据的多个版本来实现事务的隔离性。

解决的问题：

  • 提高数据库并发性能，避免读写互相阻塞
  • 在不加锁的情况下实现一致性读
  • 解决幻读、不可重复读等问题

2. MySQL中实现一致性读有哪两种方式？它们有什么区别？​

考察点： 数据库锁机制和读取方式的理解

参考答案：

区别：

  • 一致性锁定读： 需要获取锁，保证数据最新但可能阻塞
  • 一致性非锁定读： 不需要锁，读取快照数据，提高并发性

实现原理类问题​

3. MVCC的底层实现原理是什么？涉及哪些关键组件？​

考察点： 深入理解MVCC的技术实现

参考答案：

关键组件：

  1. 事务ID： 严格递增的唯一标识
  2. 行版本： 每行数据的多个版本，带有row trx_id
  3. undo log： 用于构建历史版本
  4. read-view： 事务的一致性视图

3+. Read-View 是什么？能直观解释一下吗？​

面试难点： 能不能用“时间线 + 活跃事务”解释清楚。

参考答案：
Read-View 是事务在执行一致性读时生成的快照，用来决定“哪些行版本对当前事务可见”。它的核心是 活跃事务数组。

  • m_ids：当前还未提交事务的 ID 列表
  • min_trx_id：数组里最小的事务ID（低水位）
  • max_trx_id：数组里最大的事务ID + 1（高水位，未分配）

数据可见性规则：

  1. row_trx_id < min_trx_id → 可见（比我开始还早提交）
  2. row_trx_id >= max_trx_id → 不可见（未来事务）
  3. 在 min 和 max 之间：
    • 如果 row_trx_id 在 m_ids 中 → 不可见（因为还没提交）
    • 否则可见

图解 Read-View 可见性

3++. MVCC 的底层实现原理再展开一下？​

新增要点（比原答案更细）：

  • 事务ID (trx_id)： 自增分配
  • 隐藏列 (DB_TRX_ID, DB_ROLL_PTR)： 每条记录自动维护
    • DB_TRX_ID：最近一次修改该记录的事务ID
    • DB_ROLL_PTR：指向 undo log 的回滚指针
  • Undo Log： 链接历史版本（版本链）
  • Read-View： 决定可见性

版本链示意图：

直观例子：

  • row 的当前值 name="Tom" (trx_id=25)
  • 通过 undo log 依次向下，可以找到之前是 "Jack" (trx_id=22)，再往前是 "Lucy" (trx_id=20)

隔离级别相关问题​

5. MVCC在不同隔离级别下的表现有何不同？请举例说明​

考察点： 事务隔离级别的深入理解

参考答案：

关键差异：

  • READ COMMITTED： 每次读取最新的已提交快照
  • REPEATABLE READ： 读取事务开始时的快照，保证可重复读

6. 在Go程序中如何正确使用MySQL的锁定读？​

考察点： 实际编程应用能力

参考答案：

// 错误示例：没有事务控制
func BadExample(db *sql.DB) error {
    // 这样会立即释放锁
    row := db.QueryRow("SELECT * FROM users WHERE id = ? FOR UPDATE", userID)
    return nil
}

// 正确示例：在事务中使用
func GoodExample(db *sql.DB) error {
    tx, err := db.Begin()
    if err != nil {
        return err
    }
    defer tx.Rollback()
    
    // 加排他锁
    var user User
    err = tx.QueryRow("SELECT * FROM users WHERE id = ? FOR UPDATE", userID).Scan(&user.ID, &user.Name)
    if err != nil {
        return err
    }
    
    // 执行业务逻辑
    user.Balance += 100
    
    // 更新数据
    _, err = tx.Exec("UPDATE users SET balance = ? WHERE id = ?", user.Balance, user.ID)
    if err != nil {
        return err
    }
    
    return tx.Commit()
}

// 1. 控制事务时长
func WithTimeout(ctx context.Context, db *sql.DB) error {
    ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
    defer cancel()
    
    tx, err := db.BeginTx(ctx, nil)
    if err != nil {
        return err
    }
    defer tx.Rollback()
    
    // 业务逻辑...
    
    return tx.Commit()
}

    return err
}

综合应用题​

9. 设计一个Go服务，在高并发下安全地处理用户余额变更​

考察点： 综合运用MVCC知识解决实际问题

参考答案：

type BalanceService struct {
    db *sql.DB
}

func (s *BalanceService) TransferMoney(fromUserID, toUserID int64, amount decimal.Decimal) error {
    return s.withTransaction(func(tx *sql.Tx) error {
        // 按ID排序加锁，避免死锁
        if fromUserID > toUserID {
            fromUserID, toUserID = toUserID, fromUserID
        }
        
        // 锁定转出用户
        var fromBalance decimal.Decimal
        err := tx.QueryRow("SELECT balance FROM users WHERE id = ? FOR UPDATE", fromUserID).Scan(&fromBalance)
        if err != nil {
            return err
        }
        
        // 锁定转入用户
        var toBalance decimal.Decimal
        err = tx.QueryRow("SELECT balance FROM users WHERE id = ? FOR UPDATE", toUserID).Scan(&toBalance)
        if err != nil {
            return err
        }
        
        // 检查余额
        if fromBalance.LessThan(amount) {
            return errors.New("insufficient balance")
        }
        
        // 执行转账
        _, err = tx.Exec("UPDATE users SET balance = balance - ? WHERE id = ?", amount, fromUserID)
        if err != nil {
            return err
        }
        
        _, err = tx.Exec("UPDATE users SET balance = balance + ? WHERE id = ?", amount, toUserID)
        return err
    })
}

func (s *BalanceService) withTransaction(fn func(*sql.Tx) error) error {
    tx, err := s.db.Begin()
    if err != nil {
        return err
    }
    defer tx.Rollback()
    
    if err := fn(tx); err != nil {
        return err
    }
    
    return tx.Commit()
}
