Langchain 怎么使用

LangChain 是什么？​

LangChain 是一个用于开发由语言模型驱动的应用程序的框架。他主要拥有 2 个能力：

  1. 可以将 LLM 模型与外部数据源进行连接
  2. 允许与 LLM 模型进行交互
提示

LLM 模型：Large Language Model，大型语言模型

该框架被组织为七个模块，每个模块允许您管理与LLM交互的不同方面。

以下是 LangChain 的一些常见应用：

  • 使用自然语言查询数据集：大语言模型可以使用自然语言编写 SQL 查询。LangChain 的文档加载器、索引相关链和输出解析器帮助加载和解析数据以生成结果。另外，向 LLM 输入数据结构是一种更常见的方法。

  • 与 API 交互：LangChain 的链和代理功能使用户能够将大语言模型与其他 API 调用一起包含在更长的工作流程中。这对于用例很有用，例如检索库存数据或与云平台交互。

  • 建立一个聊天机器人：生成式人工智能为行为逼真的聊天机器人带来了希望，LangChain 的 prompt 模板可以控制聊天机器人的个性和反应。消息历史记录工具通过为聊天机器人提供比默认情况下大语言模型提供的更长的内存，可以在会话中甚至跨多个会话中实现更大的一致性。

相关概念详细说明​

Chain 链​

很多时候，要解决任务，对 LLM 的单个 API 调用是不够的。该模块允许集成其他工具。例如，您可能需要从特定的 URL 获取数据，总结返回的文本，并使用生成的摘要回答问题。该模块允许连接多个工具以解决复杂的任务。

prompts 模板​

prompts 是任何 NLP 应用程序的核心。它是用户如何与模型交互以尝试从模型中获得输出。知道如何写一个有效的 prompt 是很重要的。LangChain 提供了允许用户格式化输入和其他实用程序的 prompt 模板。

文件加载器和 Utils​

LangChain 的文档加载器和 Utils 模块分别方便连接到数据源和计算。utils 模块提供了 Bash 和 Python 解释器会话。这些适用于用户需要直接与底层系统交互的应用程序，或者需要代码片段来计算特定的数学量或解决问题而不是立即计算答案的应用程序。

Agent 代理​

代理作为一个中枢，会利用 LLM 的能力做出决定、采取行动、观测完成的步骤，并循环任务，直到整个任务完成。LangChain 库提供了可以根据输入而不是硬编码的确定性序列采取操作的代理。

我们可以简单的理解为他可以动态的帮我们选择和调用 chain 或者已有的工具。 执行过程可以参考下面这张图：

Indexes 索引​

当与特定于应用程序的数据结合使用时，语言模型会变得更加强大——该模块包含用于加载、查询和更新外部数据的接口和集成。

Memory 内存​

该模块使用户能够在模型调用之间创建持久状态，能够使用记住过去所说的内容的模型来改进我们的应用程序（的任务）。

Embedding​

用于衡量文本的相关性。这个也是 OpenAI API 能实现构建自己知识库的关键所在。

他相比 fine-tuning 最大的优势就是，不用进行训练，并且可以实时添加新的内容，而不用加一次新的内容就训练一次，并且各方面成本要比 fine-tuning 低很多。

提示

Fine-tuning（微调）是指那些已经在一个大型数据集上进行过训练，学习到了一些通用特征或者知识的模型。这些模型通常会被用作迁移学习的基础，也就是说，你可以在这个已经训练好的模型的基础上，继续训练（也就是进行 fine-tuning），以适应你特定的任务。

例如，你可能有一个图像分类任务，你需要的是一个模型，它可以对你的特定类别的图片进行分类。你可以选择从头开始训练一个深度神经网络，但是这样需要大量的标注数据和计算资源。

另一种更常见的做法是，使用一个在大规模数据集（比如 ImageNet ）上预训练的模型（比如 ResNet，VGG 等），然后在你的特定数据集上对这个模型进行微调。这种方式可以大大减少训练时间和所需的数据量。因此，预训练模型是可以直接使用的，但是为了达到最好的效果，通常我们会根据特定的任务对模型进行进一步的微调。

微调就是在大模型的数据基础上做二次训练，事先准备好一批 prompt-complition(类似于问答Q&A)的数据，生成新的模型，这个模型将会包含微调后的数据。而嵌入则是每次向 ChatGPT 发送消息(prompt)的时候，把你自己数据结果带上。

王建硕老师对于微调和嵌入有过精妙的比喻：

ChatGPT就像一个已经训练好的家政阿姨，她懂中文，会做家务，但是对你家里的情况不了解。

  • 微调就相当于阿姨第一次到你家干活的时候，你要花一小时时间告诉她家里的情况，比如物件的摆放、哪些地方不能动，哪些地方要重点照顾。
  • 嵌入就相当于你省去了对阿姨进行二次培训的，而是在家里贴满纸条，这样阿姨一看到纸条就知道该怎么做了。

嵌入的搜索提问方式相对于微调有一个缺点就是它每次附带的文本数量是有限制的，因为除了原始的问题，它还需要带上搜索出来的问题，GPT-3.5是4K(大约5页)，GPT-4最大是32K(大约40页)。

就好比你有成书架的教科书可以借鉴，但每次却只能翻看其中几页笔记。

如果你想构建一个对大量文本问答的系统，OpenAI 建议 “搜索-问”(Search-Ask)的方法。

也就是先在本地文档库中 Search，拿到本地的数据结果，再去 Ask，把搜索结果和问题一起交给 GPT，这样 GPT 可以根据你提供的内容以及它模型中的数据，一起将结果返还给你。

至于如何搜索，并非一定要基于向量的搜索，可以有多重搜索方式：

  • 基于关键字搜索
  • 基于图形的搜索
  • 基于向量的搜索

至于在技术上如何实现，OpenAI 的 Cookbook 上也有详细的介绍。

两者的具体区别参考 https://www.youtube.com/watch?v=9qq6HTr7Ocw

使用 LLM Model​

可以使用 LLM Model 编写第一个对话例子

#!/usr/bin/env python
# -*- coding:utf-8 -*-

from langchain.llms import OpenAI
import os

os.environ["OPENAI_API_BASE"] = 'https://xxxxxxxxxx/v1'
os.environ["OPENAI_API_KEY"] = 'sk-xxxxxxxxxxxxxF5r'

llm = OpenAI(model_name="text-davinci-003", max_tokens=1024)
print(llm("讲一个笑话吧"))

注意，这里的 text-davinci-003 模型相比普通的 Chat Model 会消耗更多的 Tokens，所以这里尽量少用

提示

这里的 llm("讲一个笑话吧") 是将对象 llm 当作可调用函数来使用，传递参数 "讲一个笑话吧" 给该函数。

在Python中，可以通过在类中定义特殊方法 __call__() 来使对象可调用。当你调用一个对象作为函数时，Python会查找该对象是否具有 __call__() 方法，如果有，则执行该方法。

在这个例子中，llm对象似乎定义了 __call__() 方法，使得它可以被调用并接收参数。参数 "讲一个笑话吧" 被传递给 llm 对象的 __call__() 方法，以便在内部进行处理或执行特定的操作。

需要注意的是，根据代码片段提供的信息，无法确定llm对象的具体实现细节和所期望的行为。这取决于OpenAI类的定义和 __call__() 方法的实现。

这里的 llm 函数签名定义在 .venv\Lib\site-packages\langchain\llms\base.py 里面

使用 Chat models​

聊天模型是语言模型的变体。

from langchain.chat_models import ChatOpenAI
from langchain.schema import (
    AIMessage,
    HumanMessage,
    SystemMessage
)

chat = ChatOpenAI(temperature=0)
chat.predict_messages([HumanMessage(content="Translate this sentence from English to French. I love programming.")])
# >> AIMessage(content="J'adore la programmation." additional_kwargs={} example=False)

LangChain 中当前支持的消息类型是 AIMessage 、 SystemMessage 、 HumanMessage 和 ChatMessage

可以看到它和上面的 LLM 模型还是有区别的，虽然聊天模型在后台使用语言模型，但它们和上面的接口有点不同：它们不是 “文本输入，文本输出”API，而是公开一个接口，其中 “聊天消息” 是输入和输出。

不过 LangChain 公开了一个接口，可以通过该接口与聊天模型进行交互，就像普通 LLM 一样。可以通过 predict 界面访问它。

print(chat.predict("Translate this sentence from English to French. I love programming."))
# >> J'aime programmer

Prompt templates​

这里简单介绍一下模板的使用方式

首先是 LLM 模型，这种模型比较简单

from langchain.prompts import PromptTemplate

prompt = PromptTemplate.from_template("What is a good name for a company that makes {product}?")
prompt.format(product="colorful socks")
What is a good name for a company that makes colorful socks?

如果是使用 Chat 模型就比较复杂一点了

from langchain.prompts.chat import (
    ChatPromptTemplate, 
    SystemMessagePromptTemplate,
    HumanMessagePromptTemplate,
)

# 一个系统描述模板
system_message_prompt = SystemMessagePromptTemplate.from_template(
    "You are a helpful assistant that translates {input_language} to {output_language}.")
# 一个人类输入的描述模板
human_message_prompt = HumanMessagePromptTemplate.from_template("{text}")

# 载入到聊天模板里面
chat_prompt = ChatPromptTemplate.from_messages(
    [system_message_prompt, human_message_prompt])

chat_prompt.format_messages(
    input_language="English", output_language="French", text="I love programming.")
[
    SystemMessage(content="You are a helpful assistant that translates English to French.", additional_kwargs={}),
    HumanMessage(content="I love programming.")
]

上面只是输出的模板，如果要使用模板，可以直接丢到聊天模型里面

customer_messages = chat_prompt.format_messages(
    input_language="English", output_language="Chinese", text="I love programming.")


# 创建一个聊天模型

customer_response = chat(customer_messages)

使用 Chains​

现在我们已经有了模型和提示模板，我们需要将两者结合起来。链为我们提供了一种将多个原语链接（或链接）在一起的方法，例如模型、提示和其他链。

from langchain import LLMChain
from langchain.chat_models import ChatOpenAI
from langchain.prompts.chat import (
    ChatPromptTemplate,
    SystemMessagePromptTemplate,
    HumanMessagePromptTemplate,
)

# 创建一个聊天模型
chat = ChatOpenAI(model_name="gpt-3.5-turbo", max_tokens=1024)

# 一个系统描述模板
system_message_prompt = SystemMessagePromptTemplate.from_template(
    "You are a helpful assistant that translates {input_language} to {output_language}.")
# 一个人类输入的描述模板
human_message_prompt = HumanMessagePromptTemplate.from_template("{text}")

chat_prompt = ChatPromptTemplate.from_messages(
    [system_message_prompt, human_message_prompt])

chain = LLMChain(llm=chat, prompt=chat_prompt)
customer_response = chain.run(
    input_language="English", output_language="Chinese", text="I love programming.")

print(customer_response)
#>> 我爱编程。 (Wǒ ài biānchéng.)

初识 Agent​

用户与 AI 对话产品交互过程中，往往遇到这样的情况：用户会提出不同需求，在应对不同任务的时候，AI产品可能需要借助不同的工具。如果是闲聊问题不大，用LLM自己的知识库即可，但比如用户需要对一个近期新闻事件进行评论，可能需要LLM配合搜索或者爬虫的工具。或者一款产品详情进行询问，就需要访问公司内部数据库。如何把这些能力进行集成统一在一个问答对话场景里实现。

思路如下图，简单来说就是靠 LLM 对用户的问题自己进行判定需要什么它做什么，然后告诉它，需要做X需要使用工具Y。但凡接入了具备这样能力的底座大模型，就可以这么设计产品。

代理就是这样做的：他们使用语言模型来确定要执行的操作以及顺序。Agent 可以访问工具，他们反复选择工具，运行工具并观察输出，直到他们得出最终答案。

要使用 Agent，我们需要为它提供一个模型和一个工具列表。

  • LLM：为代理提供支持的语言模型；
  • 工具：执行特定职责的功能。这可以是：谷歌搜索，数据库查找，Python REPL，其他链。有关预定义工具及其规范的列表，请参阅 工具文档。
  • Agent：引用受支持的代理类的字符串。Agent 类在很大程度上由语言模型用于确定要执行的操作的提示进行参数化。

比如我们要做一个公司的智能问答系统，需要支持公司基本情况介绍能力，公司产品描述能力。先定义数据源。

我们定义一些模拟的数据库，可以方便地扩展到其他形式的数据（各种搜索 API 等）。这个数据源可以是结构化的 KV store 比如下面的 find_product_description，也可以是需要结合 LLM 阅读理解能力生成结果的比如这里的 find_company_info。

然后下面这段是定义 Agent 的思考过程，主要是用来告诉 LLM 可以使用工具来解决问题的一系列指令，其中包括每个工具的名称和工具的用途描述。并定义了输出结构的格式即 Action 和 Action Input 后面的内容方便 OutputParser 来解析所需要的信息。

它主要是要回答这个问题需要用什么工具，给工具什么样的输入。

# 定义一个 Agent 的模板
AGENT_TMPL = """按照给定的格式回答以下问题。你可以使用下面这些工具：

{tools}

回答时需要遵循以下用---括起来的格式：

---
Question: 我需要回答的问题
Thought: 回答这个上述我需要做些什么
Action: “{tool_names}” 中的其中一个工具名
Action Input: 选择工具所需要的输入
Observation: 选择工具返回的结果
...（这个思考/行动/行动输入/观察可以重复N次）
Thought: 我现在知道最终答案
Final Answer: 原始输入问题的最终答案
---

现在开始回答，记得在给出最终答案前多按照指定格式进行一步一步的推理。

Question: {input}
{agent_scratchpad}
"""


class CustomPromptTemplate(StringPromptTemplate):
    template: str  # 标准模板
    tools: List[Tool]  # 可使用工具集合

    def format(self, **kwargs) -> str:
        """
        按照定义的 template，将需要的值都填写进去。

        Returns:
            str: 填充好后的 template。
        """
        intermediate_steps = kwargs.pop("intermediate_steps")  # 取出中间步骤并进行执行
        thoughts = ""
        for action, observation in intermediate_steps:
            thoughts += action.log
            thoughts += f"\nObservation: {observation}\nThought: "
        kwargs["agent_scratchpad"] = thoughts  # 记录下当前想法
        kwargs["tools"] = "\n".join(
            [f"{tool.name}: {tool.description}" for tool in self.tools]
        )  # 枚举所有可使用的工具名+工具描述
        kwargs["tool_names"] = ", ".join(
            [tool.name for tool in self.tools]
        )  # 枚举所有的工具名称
        cur_prompt = self.template.format(**kwargs)
        print(cur_prompt)
        return cur_prompt


class CustomOutputParser(AgentOutputParser):
    def parse(self, llm_output: str) -> Union[AgentAction, AgentFinish]:
        """
        解析 llm 的输出，根据输出文本找到需要执行的决策。

        Args:
            llm_output (str): _description_

        Raises:
            ValueError: _description_

        Returns:
            Union[AgentAction, AgentFinish]: _description_
        """
        if "Final Answer:" in llm_output:  # 如果句子中包含 Final Answer 则代表已经完成
            return AgentFinish(
                return_values={"output": llm_output.split("Final Answer:")[-1].strip()},
                log=llm_output,
            )

        regex = r"Action\s*\d*\s*:(.*?)\nAction\s*\d*\s*Input\s*\d*\s*:[\s]*(.*)"  # 解析 action_input 和 action
        match = re.search(regex, llm_output, re.DOTALL)
        if not match:
            raise ValueError(f"Could not parse LLM output: `{llm_output}`")
        action = match.group(1).strip()
        action_input = match.group(2)

        return AgentAction(
            tool=action, tool_input=action_input.strip(" ").strip('"'), log=llm_output
        )

# 实例化一个自己定义的数据源
fuge_data_source = FugeDataSource(llm)

# 定义一些工具
tools = [
    Tool(
        name="查询产品名称",
        func=fuge_data_source.find_product_description,
        description="通过产品名称找到产品描述时用的工具，输入应该是产品名称",
    ),
    Tool(
        name="XXX科技公司相关信息",
        func=fuge_data_source.find_company_info,
        description="当用户询问公司相关的问题，可以通过这个工具了解相关信息",
    ),
]

# 定义一个 Agent 模板
agent_prompt = CustomPromptTemplate(
    template=AGENT_TMPL,
    tools=tools,
    input_variables=["input", "intermediate_steps"],
)

output_parser = CustomOutputParser()

# 实例化一个 LLMChain，这个 LLMChain 就是一个 LLM 的链条，可以用来执行 LLM
# 可以发现这里其实就是通过文本的方式把 Agent 模板和上面给的函数给串联起来了
llm_chain = LLMChain(llm=llm, prompt=agent_prompt)

tool_names = [tool.name for tool in tools]

# 实例化一个 Agent，LLMSingleActionAgent 是一个单步执行的 Agent，也就是说每次只会执行一个工具
agent = LLMSingleActionAgent(
    llm_chain=llm_chain,
    output_parser=output_parser,
    stop=["\nObservation:"],
    allowed_tools=tool_names,
)

# 实例化一个 AgentExecutor，这就是一个执行器，用来执行 Agent
agent_executor = AgentExecutor.from_agent_and_tools(
    agent=agent, tools=tools, verbose=True
)

使用 Fake LLM​

可以使用 Fake LLM 来测试一下，这个 Fake LLM 是一个随机生成的模型，它会随机返回一些文本，这样就不用消耗 OpenAI 的 Tokens 了。

from langchain.llms.fake import FakeListLLM
from langchain.agents import load_tools
from langchain.agents import initialize_agent 
from langchain.agents import AgentType

tools = load_tools(["python_repl"])

responses = [
    "Action: Python REPL\nAction Input: print(2 + 2)", "Final Answer: 4"]

llm = FakeListLLM(responses=responses)

# 工具加载后都需要初始化，verbose 参数为 True，会打印全部的执行详情
agent = initialize_agent(
    tools, llm, agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION, verbose=True
)

print(agent.run("print(2 + 2)"))
