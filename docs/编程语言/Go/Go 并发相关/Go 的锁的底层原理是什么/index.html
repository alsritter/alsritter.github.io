Go 的锁的底层原理详解

1. Mutex 基本结构与状态​

type Mutex struct {
    state int32   // 锁的状态字段，包含多个标志位
    sema  uint32  // 信号量，用于阻塞和唤醒goroutine
}

state 字段的位标志详解​

各字段含义：

  • mutexLocked (0位)：表示锁是否被持有
  • mutexWoken (1位)：表示是否有 goroutine 从 sleep 状态被唤醒
  • mutexStarving (2位)：表示是否处于饥饿模式
  • waiterCount (3-31位)：等待获取锁的 goroutine 数量

2. 锁的两种工作模式​

正常模式 vs 饥饿模式​

特性正常模式饥饿模式
新来的G可以抢占锁直接排队
性能高（减少上下文切换）低（严格排队）
公平性不公平绝对公平
触发条件默认模式等待时间 > 1ms

3. 加锁过程详解​

加锁的核心代码流程​

func (m *Mutex) Lock() {
    // 快速路径：如果锁未被持有，直接获取
    if atomic.CompareAndSwapInt32(&m.state, 0, mutexLocked) {
        return
    }
    // 慢速路径
    m.lockSlow()
}

func (m *Mutex) lockSlow() {
    var waitStartTime int64
    starving := false
    awoke := false
    iter := 0
    old := m.state
    
    for {
        // 1. 自旋条件检查
        if old&(mutexLocked|mutexStarving) == mutexLocked && runtime_canSpin(iter) {
            // 尝试设置 mutexWoken 标志
            if !awoke && old&mutexWoken == 0 && old>>mutexWaiterShift != 0 &&
                atomic.CompareAndSwapInt32(&m.state, old, old|mutexWoken) {
                awoke = true
            }
            runtime_doSpin()  // 自旋等待
            iter++
            old = m.state
            continue
        }
        
        // 2. 计算新的state值
        new := old
        if old&mutexStarving == 0 {
            new |= mutexLocked  // 非饥饿模式才尝试获锁
        }
        if old&(mutexLocked|mutexStarving) != 0 {
            new += 1 << mutexWaiterShift  // 增加等待者计数
        }
        if starving && old&mutexLocked != 0 {
            new |= mutexStarving  // 设置饥饿模式
        }
        if awoke {
            new &^= mutexWoken  // 清除唤醒标志
        }
        
        // 3. CAS 更新 state
        if atomic.CompareAndSwapInt32(&m.state, old, new) {
            // 4. 处理获锁成功的情况
            if old&(mutexLocked|mutexStarving) == 0 {
                break  // 获锁成功
            }
            
            // 5. 需要休眠等待
            queueLifo := waitStartTime != 0
            if waitStartTime == 0 {
                waitStartTime = runtime_nanotime()
            }
            runtime_SemacquireMutex(&m.sema, queueLifo, 1)
            
            // 6. 被唤醒后检查是否需要进入饥饿模式
            starving = starving || runtime_nanotime()-waitStartTime > starvationThresholdNs
            old = m.state
            
            // 7. 饥饿模式下的处理
            if old&mutexStarving != 0 {
                delta := int32(mutexLocked - 1<<mutexWaiterShift)
                if !starving || old>>mutexWaiterShift == 1 {
                    delta -= mutexStarving  // 退出饥饿模式
                }
                atomic.AddInt32(&m.state, delta)
                break
            }
            awoke = true
            iter = 0
        } else {
            old = m.state
        }
    }
}

4. 被锁住的 Goroutine 状态变化​

Goroutine 的具体状态​

// Goroutine 状态定义
const (
    _Gidle = iota     // 刚分配，还未初始化
    _Grunnable       // 在运行队列中，等待被调度
    _Grunning        // 正在执行
    _Gsyscall        // 执行系统调用
    _Gwaiting        // 被阻塞 (等待锁、channel等)
    _Gdead           // 执行完毕
)

被锁阻塞的 Goroutine 状态变迁：

  1. _Grunning → _Gwaiting：调用 runtime_SemacquireMutex 时
  2. _Gwaiting → _Grunnable：被 runtime_Semrelease 唤醒时
  3. _Grunnable → _Grunning：被调度器重新调度时

5. 解锁过程详解​

解锁的核心代码​

func (m *Mutex) Unlock() {
    // 快速路径：直接减去 locked 标志
    new := atomic.AddInt32(&m.state, -mutexLocked)
    if new != 0 {
        m.unlockSlow(new)  // 有等待者，进入慢速路径
    }
}

func (m *Mutex) unlockSlow(new int32) {
    // 检查是否在未加锁状态下调用 Unlock
    if (new+mutexLocked)&mutexLocked == 0 {
        panic("sync: unlock of unlocked mutex")
    }
    
    if new&mutexStarving == 0 {
        // 正常模式
        old := new
        for {
            // 如果没有等待者或锁已被获取，直接返回
            if old>>mutexWaiterShift == 0 || old&(mutexLocked|mutexWoken|mutexStarving) != 0 {
                return
            }
            // 设置 mutexWoken 标志，减少等待者计数
            new = (old - 1<<mutexWaiterShift) | mutexWoken
            if atomic.CompareAndSwapInt32(&m.state, old, new) {
                runtime_Semrelease(&m.sema, false, 1)  // 唤醒一个等待者
                return
            }
            old = m.state
        }
    } else {
        // 饥饿模式：直接传递锁给等待队列的第一个goroutine
        runtime_Semrelease(&m.sema, true, 1)
    }
}

6. 信号量机制​

信号量操作​

// 等待信号量 (阻塞当前goroutine)
func runtime_SemacquireMutex(s *uint32, lifo bool, skipframes int)

// 释放信号量 (唤醒等待的goroutine)  
func runtime_Semrelease(s *uint32, handoff bool, skipframes int)

参数说明：

  • lifo: 是否以 LIFO 方式排队
  • handoff: 是否直接传递锁（饥饿模式）
  • skipframes: 用于调试的栈帧跳过数量

8. 性能优化策略​

自旋的条件​

const active_spin = 4  // 最大自旋次数

func runtime_canSpin(i int) bool {
    return i < active_spin &&      // 自旋次数 < 4
           runtime.GOMAXPROCS(0) > 1 &&  // 多核CPU
           runtime.NumGoroutine() > 1 &&  // 有其他G在运行
           runtime.NumP() > 1             // 有空闲的P
}

减少锁竞争的方法​

  1. 减少锁的持有时间
// 不好的做法
mu.Lock()
data := heavyComputation()  // 耗时操作
sharedMap[key] = data
mu.Unlock()

// 好的做法  
data := heavyComputation()  // 在锁外进行计算
mu.Lock()
sharedMap[key] = data
mu.Unlock()
  1. 使用读写锁
var rwmu sync.RWMutex

// 读操作使用读锁
rwmu.RLock()
value := sharedMap[key]
rwmu.RUnlock()

// 写操作使用写锁
rwmu.Lock()
sharedMap[key] = value
rwmu.Unlock()
  1. 锁分段
type SegmentedMap struct {
    segments []segment
    mask     uint32
}

type segment struct {
    mu   sync.Mutex
    data map[string]interface{}
}

func (sm *SegmentedMap) Get(key string) interface{} {
    seg := &sm.segments[hash(key)&sm.mask]
    seg.mu.Lock()
    defer seg.mu.Unlock()
    return seg.data[key]
}

9. 总结​

Go Mutex 的关键特性：

  • 两种模式：正常模式（性能优先）和饥饿模式（公平性优先）
  • 自适应：根据竞争情况自动切换模式
  • 自旋优化：减少不必要的上下文切换
  • 防止饥饿：确保等待时间过长的 goroutine 能够获得锁

被锁阻塞的 Goroutine：

  • 先尝试 自旋 (消耗 CPU，但避免上下文切换)
  • 自旋失败后进入 休眠状态 (_Gwaiting)
  • 被唤醒后进入 运行队列 (_Grunnable)
  • 等待调度器重新调度

这种设计在高并发场景下能够很好地平衡性能和公平性！
